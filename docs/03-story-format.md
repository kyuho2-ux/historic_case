# 03. 스토리 포맷 & 신뢰성 가이드

## 1. 에피소드 기본 구조: "CASE" 6단계

모든 에피소드는 같은 뼈대를 쓴다. 제작이 빨라지고, 시청자는 익숙한 리듬을 기대하게 된다.

| 단계 | 이름 | 분량 (15분 영상 기준) | 할 일 |
|---|---|---|---|
| 1 | **Cold Open (결정 직전 장면)** | 0:00~0:40 | 가장 긴장된 순간에서 시작. 결말은 말하지 않는다 |
| 2 | **Background (되감기)** | ~3:00 | 시대, 인물, 이해관계. "왜 이 상황이 됐나" |
| 3 | **Dilemma (나라면?)** | ~5:00 | 선택지 2~3개를 제시하고 시청자에게 질문. 댓글 참여 유도 지점 |
| 4 | **Decision & Result** | ~10:00 | 실제로 무엇을 선택했고 어떻게 됐는지 |
| 5 | **Twist / Myth Check** | ~12:30 | 잘 알려지지 않은 사실, 통념과 다른 점, 학계의 다른 해석 |
| 6 | **Lesson Card** | ~15:00 | 교훈 한 줄 + 오늘 적용 질문 1개 + 출처 안내 |

> 3번 "나라면?" 질문과 6번 "교훈 카드"는 강연·워크숍에서 그대로 **토론 질문**과 **슬라이드**가 된다.

## 2. 신뢰성 가이드

역사 콘텐츠의 가장 큰 자산은 신뢰이고, 가장 큰 리스크는 틀린 정보다. 강연 섭외 담당자는 반드시 출처를 본다.

### 2-1. 출처 등급

| 등급 | 종류 | 예 | 사용 원칙 |
|---|---|---|---|
| S | 1차 사료 | 조선왕조실록, 의궤, 당대 공문서·편지·일기 | 인용 시 원문 위치 표기 |
| A | 학술 연구 | 논문, 대학 출판부 도서, 박물관 공식 자료 | 핵심 주장의 근거로 사용 |
| B | 신뢰할 만한 대중서·언론 | 저자·출처가 명확한 교양서, 주요 언론 기사 | 보조 근거, 가능하면 A로 교차 확인 |
| C | 2차 요약 | 위키백과, 블로그, 유튜브 | **출발점으로만 사용**, 단독 근거 금지 |

**원칙:** 에피소드의 핵심 주장(숫자, 인용문, 인과관계)은 **A등급 이상 1개 + 다른 출처 1개**로 교차 확인한다.

### 2-2. 사실 / 해석 / 논쟁 구분 표기

스크립트와 글에서 세 가지를 명확히 구분해 말한다.

- **사실:** "1628년 8월 10일, 바사호는 처녀항해에서 침몰했습니다."
- **해석:** "많은 역사가들은 그 원인으로 설계 변경과 무리한 일정을 꼽습니다."
- **논쟁:** "적기조례가 영국 자동차 산업을 뒤처지게 했다는 주장이 있지만, 그 영향의 크기에 대해서는 의견이 갈립니다."

### 2-3. 자주 틀리는 것들 체크리스트

- [ ] 유명한 '명언'이 실제 발언인지 (영화·후대 창작인 경우가 많음)
- [ ] 숫자(사망자, 금액, 병력)의 출처와 추정치 여부
- [ ] 날짜 표기 (율리우스력/그레고리력, 음력/양력)
- [ ] 현재 가치 환산 금액의 기준
- [ ] 인물에 대한 도덕적 평가를 사실처럼 말하고 있지 않은지
- [ ] 이미지·지도·영상 소스의 저작권 (퍼블릭 도메인/라이선스 확인)

### 2-4. 오류 정정 정책

- 오류 지적이 오면 확인 후 **고정 댓글 / 글 상단에 정정 내용 공개**.
- 정정 기록을 모아 두는 것 자체가 신뢰 자산이다. "우리는 틀리면 고친다"를 브랜드로 삼는다.

## 3. 원 소스 멀티 유즈: 한 편을 5가지로

리서치 1회로 아래 결과물을 순서대로 만든다.

```
[리서치 노트 + 출처 목록]
        │
        ├─① 글 (뉴스레터 / 블로그 / 브런치)   2,500~4,000자   ← 가장 먼저. 반응 테스트
        │
        ├─② 롱폼 영상 (유튜브)               12~18분         ← 글 반응 좋은 소재 우선
        │
        ├─③ 숏폼 3~5개 (쇼츠·릴스·틱톡)      45~60초         ← 훅/반전/교훈 장면을 각각 잘라냄
        │
        ├─④ 케이스 카드 (PDF 1~2쪽)          교훈 + 토론 질문  ← 전자책·강연 교재의 조각
        │
        └─⑤ 강연 모듈 (슬라이드 10~15장)       20~30분 분량      ← 3~4개 모듈을 묶어 90분 강연
```

### 포맷별 포인트

| 포맷 | 핵심 | 성공 기준 |
|---|---|---|
| 글 | 제목 = 질문형 훅, 소제목으로 CASE 6단계 | 오픈율, 끝까지 읽은 비율, 답장/공유 수 |
| 롱폼 영상 | 첫 30초 이탈 방지, 지도·사료 이미지로 신뢰감 | 평균 시청 지속률, 구독 전환 |
| 숏폼 | "~한 거 알아?" 반전 한 방, 롱폼으로 유도 | 조회수, 프로필 유입 |
| 케이스 카드 | 한 장에 스토리 요약·교훈·질문 | 다운로드 수 (이메일 수집 도구로 활용) |
| 강연 모듈 | 스토리 → 토론 → 프레임워크 → 우리 조직 적용 | 청중 만족도, 재섭외율 |

## 4. 제작 워크플로 (1편 기준, 1인 제작 가정)

| 단계 | 소요 (예상) | 산출물 |
|---|---|---|
| 소재 선정 & 사전 조사 | 0.5일 | 소재가 CASE 구조에 맞는지, 출처가 충분한지 판단 |
| 리서치 & 팩트체크 | 1~2일 | 리서치 노트, 출처 목록(등급 표기) |
| 글 작성 | 1일 | 뉴스레터/블로그 원고 |
| 영상 스크립트 전환 | 0.5일 | 구어체 스크립트 + 장면 메모 |
| 녹음·편집 | 1~3일 | 롱폼 1편 + 숏폼 3~5개 (외주 시 단축) |
| 카드·모듈화 | 0.5일 | 케이스 카드, 강연 슬라이드 |

> 초기에는 **주 1편 글 + 격주 1편 영상** 정도가 1인이 지속 가능한 속도다. 편집은 가장 먼저 외주로 넘길 후보.
>
> 리서치 보조, 스크립트 초안, 자막 정리에 AI 도구를 쓸 수 있지만, **사실 관계는 반드시 원 출처로 직접 확인**한다. AI가 만든 그럴듯한 인용문과 숫자는 이 채널의 가장 큰 리스크다.
